What 0 and 1 mean

Each number in fₜ is a dial for one slot on the belt:
1.0  → KEEP this memory fully       ✅
0.5  → keep HALF of it
0.0  → FORGET it completely          ❌

📄 Page 2: Putting it all together, the memory update

The most important formula of LSTM

Cₜ = fₜ * Cₜ₋₁   +   iₜ * C̃ₜ
     └───┬───┘       └──┬──┘
   Removing or      Candidate
   Forgetting       memory
   some info        (adding info)
(Your notes write these labels under the two halves.)

Here * means pointwise multiply (same as ⊗).

Read it like a sentence:

▎ new belt = (old belt after forgetting) + (filtered new info)


┌───────────┬─────────────────────────────────────┬───────────────────────────────────────────────────┐
│   Piece   │             Comes from              │                      Meaning                      │
├───────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ fₜ * Cₜ₋₁ │ forget gate (last class)            │ old memory, with some parts removed               │
├───────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ iₜ * C̃ₜ   │ input gate × candidate (this class) │ new memory, only the useful parts                 │
├───────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ +         │ the ⊕ on the belt                   │ combine them                                      │
├───────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ Cₜ        │ result                              │ the new long-term memory, passed to the next word │
└───────────┴─────────────────────────────────────┴───────────────────────────────────────────────────┘

Your notes on the right say the same thing:
Forget Gate
   +
I/p Gate ⊗ Candidate memory
Cₜ₋₁ ⇒ Cₜ

The picture (page 2, left)

The red arrow goes over the top from Cₜ₋₁ to Cₜ, along the belt:
1. First ⊗, where the forget gate fₜ comes up from below (removing)
2. Then ⊕, where iₜ ⊗ C̃ₜ comes up from below (adding)

Full worked example (using numbers from all your PDFs)

Take the belt and forget gate from last class, and the new info from this class:
Cₜ₋₁       = [6,   8,   9  ]    ← old belt
fₜ         = [0.5, 1,   0.5]    ← forget gate (example ③ from last class)
iₜ * C̃ₜ   = [0,   8,   0  ]    ← new info (this class)

Step 1: forget (⊗)
fₜ * Cₜ₋₁ = [6×0.5, 8×1, 9×0.5] = [3, 8, 4.5]

Step 2: add (⊕), position by position:
[3,    8,    4.5]
+
[0,    8,    0  ]
=
[3+0,  8+8,  4.5+0] = [3, 16, 4.5]

New belt: Cₜ = [3, 16, 4.5]
- Slot 1: half forgotten, nothing new → 3
- Slot 2: kept fully and new info added → 16 (much stronger now)
- Slot 3: half forgotten, nothing new → 4.5


The India example (page 2)

▎ "I stay in India …………… and I speak ___"
▎ Options: English or Hindi

How the LSTM handles this, step by step:

1. At the word "India":
   - candidate memory C̃ₜ creates the info "the country is India"
   - the input gate sees it's important and opens, so it gets added to the belt
2. During the many words in between (……):
   - the forget gate keeps that slot close to 1, so "India" stays on the belt
   - unimportant words get input gate ≈ 0, so nothing junk is added
3. At "I speak ___":
   - the belt still holds "India", so the model can pick Hindi over English ✅

That's exactly the long-term dependency a plain RNN failed at (first PDF). LSTM solves it with forget + input + candidate working together.


Why two separate helpers instead of one?

- tanh (candidate) gives values from -1 to 1, so it can push memory up or down. It carries the content.
- σ (input gate) gives values from 0 to 1, so it works as a volume knob. It carries the decision.

Splitting "what is the info" from "should I add it" lets the LSTM prepare new info every time but add it only when it matters.

Part 1: ③ Output Gate

The big idea first

So far the LSTM has updated its long-term memory (the belt, Cₜ):
- forget gate → removed old info
- input gate + candidate → added new info

The question now is: what should the LSTM show or pass on at this step? That's the job of the output gate.

The picture (top-left)

- The highlighted σ box, with W_o and b_o underneath, is the output gate. Your arrow points to it and says "Neural Network": it's another tiny Dense layer, just like the other gates.
- Cₜ (boxed) → "Memory Cell": the new belt from last class.
- Cₜ goes down through tanh, then into ⊗, where it gets multiplied by oₜ.
- What comes out is hₜ, going right (to the next word) and up (as the output).


The two formulas

oₜ = σ( W_o · [hₜ₋₁, xₜ] + b_o )      ← output gate (the dial)
hₜ = oₜ * tanh(Cₜ)                     ← new short-term memory


Formula 1: oₜ, the output gate

It has exactly the same shape as the other gates:

┌───────────┬───────────────────────────────────┬──────────┐
│   Gate    │              Formula              │ Squeezer │
├───────────┼───────────────────────────────────┼──────────┤
│ Forget    │ fₜ = σ(W_f · [hₜ₋₁, xₜ] + b_f)    │ σ        │
├───────────┼───────────────────────────────────┼──────────┤
│ Input     │ iₜ = σ(Wᵢ · [hₜ₋₁, xₜ] + bᵢ)      │ σ        │
├───────────┼───────────────────────────────────┼──────────┤
│ Candidate │ C̃ₜ = tanh(W_c · [hₜ₋₁, xₜ] + b_c) │ tanh     │
├───────────┼───────────────────────────────────┼──────────┤
│ Output    │ oₜ = σ(W_o · [hₜ₋₁, xₜ] + b_o)    │ σ        │
└───────────┴───────────────────────────────────┴──────────┘

- The same glued input [hₜ₋₁, xₜ] (7 numbers in your example)
- Its own weights W_o (7×3) and its own biases b_o (3)
- σ → every value is between 0 and 1 → a dial for each slot
  - 1 = "show this slot fully"
  - 0 = "hide this slot"


Formula 2: hₜ = oₜ * tanh(Cₜ)

Two small steps:

Step A: tanh(Cₜ), squeeze the belt
The belt numbers can get big (last class we got 16). Before showing them, tanh squeezes each one to between -1 and 1, so the short-term memory stays small and safe.

⚠️ Note: this tanh has no weights. It's just the squeezer (a pointwise operation, the pink circle in the legend). It is not a neural network layer.


Step B: oₜ * …, apply the dial
Pointwise multiply. Each slot is shown fully, partly, or not at all.


Worked example (continuing from last class)

Last class we ended with:
Cₜ = [3, 16, 4.5]        ← new belt

Step A: squeeze with tanh
tanh(3)   ≈ 0.995
tanh(16)  ≈ 1.000
tanh(4.5) ≈ 1.000

tanh(Cₜ) ≈ [0.995, 1.0, 1.0]
(Big numbers all get squeezed to almost 1, so nothing can blow up.)

Step B: the output gate decides (made-up values):
oₜ = [1, 0, 0.5]


Multiply position by position:

┌──────┬──────────┬─────┬───────────┬─────────────────────┐
│ Slot │ tanh(Cₜ) │ oₜ  │ Multiply  │         hₜ          │
├──────┼──────────┼─────┼───────────┼─────────────────────┤
│ 1    │ 0.995    │ 1   │ 0.995 × 1 │ 0.995 (shown fully) │
├──────┼──────────┼─────┼───────────┼─────────────────────┤
│ 2    │ 1.0      │ 0   │ 1.0 × 0   │ 0 (hidden)          │
├──────┼──────────┼─────┼───────────┼─────────────────────┤
│ 3    │ 1.0      │ 0.5 │ 1.0 × 0.5 │ 0.5 (half shown)    │
└──────┴──────────┴─────┴───────────┴─────────────────────┘

hₜ = [0.995, 0, 0.5]     ← new short-term memory

Important: slot 2 is hidden from hₜ, but it is still on the belt (Cₜ still has 16 there). The output gate only decides what to show now. It doesn't delete anything. That info can be shown later, when it's needed.


Real-life example:

▎ "I grew up in India … I love cricket … I speak fluent ___"

- At "cricket", the "India" slot is still on the belt, but the output gate may hide it (not needed right now).
- At "I speak fluent", the output gate opens the "India" slot so the model can predict Hindi.


Part 4: Training, updating the weights


Small addition: your note lists Wᵢ, W_c and W_o, but W_f (the forget gate weights) gets updated too, along with all 4 biases (b_f, bᵢ, b_c, b_o). The full list:
[W_f, Wᵢ, W_c, W_o]  +  [b_f, bᵢ, b_c, b_o]   ← all updated by back propagation


Counting the weights (your example sizes)

Each gate = a tiny Dense layer: (7 × 3) weights + 3 biases = 24.
forget gate      : 24
input gate       : 24
candidate memory : 24
output gate      : 24
                   ---
total LSTM       : 96   = 4 × 24
An LSTM has 4 times the weights of a SimpleRNN of the same size, because it has 4 little networks inside instead of 1.

General formula:
LSTM weights = 4 × ( units × (embedding_dim + units) + units )
With the earlier model (Embedding(output_dim=10), units=12):
SimpleRNN(12): (10 + 12 + 1) × 12      = 276
LSTM(12)     : 4 × 276                 = 1,104
